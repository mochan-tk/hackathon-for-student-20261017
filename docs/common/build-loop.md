# 実装して、確かめながら完成へ進める

このリポジトリは汎用の Vite + React + TypeScript スターターです。[締切管理の例](../examples/deadline.md)を完成済みのアプリとして含むものではありません。まず[product.md](../product.md)を自分たちの企画で埋め、チームで完成条件を確認します。

## 1. 起動と確認の方法をそろえる

Node.js 24 LTSを使います。リポジトリのルートで、依存関係をそろえて開発サーバーを起動します。

```bash
npm ci
npm run dev
```

SWA CLIの4280番を開き、画面が見えることを確かめます。PC・Codespacesでの開き方とAPIの追加は[共通の開発環境](local-development.md)を参照してください。

## 2. Planで作業と検証を決める

CopilotのPlanを使い、企画・画面・既存コードを読ませます。完成条件を作業単位に分け、「作るもの」「対応するDoD」「確かめ方」の草案を会話に出してもらいます。Planではファイルを編集できない場合があります。チームで確認した計画は、実装できるモードへ切り替えてから[tasks.md](../tasks.md)へ保存します。

```text
docs/product.md と画面設計、既存コードを読んでください。
Planで、必須機能を完成させる作業と検証方法の草案を会話に出してください。
仕様が未入力なら先に必要な点を確認してください。まだファイルの編集や実装はしないでください。
```

チームは、必須機能の漏れと不要な追加がないかを確認します。小さな文言修正まで毎回新しい計画を作る必要はありません。

## 3. AIに実装・検証・修正を続けてもらう

```text
承認した計画を最初に docs/tasks.md へ保存し、確認済みの docs/product.md と計画に沿って実装してください。
作業に必要なコードを読み、完成条件を確かめるテストを用意して実行してください。
npm run check と npm run test:e2e、必要な動作確認で失敗があれば原因を直し、再確認してください。
完成条件に足りない点があれば実装へ戻り、条件を満たすまで進めてください。
仕様を勝手に広げず、追加支出、有料サービスの契約、秘密情報が必要になる作業は実行前に対象と理由を説明してください。
権限不足や同じ不具合で進展がない場合、またはチームが決めた上限に達した場合は、試したことと再開に必要な情報を報告してください。
終了時に変更内容、実行した確認と結果、未達・未確認を docs/verification.md に残してください。
```

ブラウザテストの初回だけ、次を実行します。

```bash
npx playwright install chromium
```

自動確認は次のコマンドです。

```bash
npm run check
npm run test:e2e
```

`check` はlint・型・buildの確認、`test:e2e` はブラウザでの自動確認です。スターターのテストが通っただけでは、自分たちのDoDを満たした証拠になりません。企画に合う入力・操作・期待結果へテストを追加または更新します。

## 4. 完成条件に戻って確認する

AIの完了報告を、[検証の進め方](verification.md)で確かめます。別の学生が必須DoDに対応する主要な操作経路を実際に試し、未達なら修正へ戻します。

仕様を変えたら、まず `product.md` の機能・DoD・除外範囲と画面設計を更新し、`tasks.md` とテストもそろえます。会話だけで仕様を変更しないでください。

セッションや開発環境を切り替える前に、実装済み・未完了、確認結果、次の作業を文書に残してGitで保存します。次のAIは文書とGitの変更を読み、起動・基本動作を確認してから続きを進めます。

必須条件を確認できたら、動くプレビューで発表できます。継続して共有する場合は[Azureへの公開](publish.md)へ進みます。
